# バッグ口コミサイト サイト設計書（v0.1 ドラフト）

> @cosme のバッグ版を目指す、日本語ユーザー向けバッグ専門口コミサイトの設計ドラフト。
> 競合 (@cosme / LIPS / 価格.com / 楽天みんなのレビュー / Vestiaire Collective / サンワダイレクト等) の調査を踏まえてまとめた素案です。

---

## 1. 競合分析サマリ

| サイト | 強み | 取り入れたい点 |
|---|---|---|
| **@cosme** | カテゴリ別ランキング、属性別フィルタ（年齢・肌質）、クリップ保存 | 評価軸の細かさ、ランキングの権威性、属性別レビュー絞り込み |
| **LIPS** | UGC（写真・動画）中心、SNS的フォロー、パーソナル診断 | 写真付きレビューの一覧性、タグ文化、診断による商品提案 |
| **価格.com** | スペック比較表、レビューと製品情報の融合 | スペック横並び比較 UI |
| **楽天みんなのレビュー** | 購入者バッジ、購入店からの誘導 | 「購入者」「未購入」の区別、信頼性表示 |
| **Vestiaire Collective** | 真贋認証バッジ、状態グレード（Meets/Fails 等）、出品者評価 | バッグ特有の「状態」「真贋」表示パターン |
| **サンワダイレクト / 目々澤鞄** | カテゴリ × レビュー（容量・重さ・取手） | バッグ用語に最適化されたレビュー設問 |
| **PRTimes 調査**（株式会社レビュー） | バッグ購入で参考にされる口コミ1位は「収納力」 | 収納力を最重要評価軸に据える |

**示唆**: @cosme の「ランキング権威性」+ LIPS の「写真UGC文化」+ 価格.com の「スペック比較」を**バッグドメイン**に翻訳するのが勝ち筋。

## 2. ターゲットユーザー & ユースケース

### ペルソナ
1. **20代後半 OL「美咲」**: 新しい通勤バッグを買いたい。A4 が入って軽くて、コーデに合わせやすいものを探したい。失敗したくない。
2. **30代主婦「彩」**: マザーズバッグを物色中。容量と仕切り、軽さが命。Instagram で見たやつのリアルな評価を知りたい。
3. **40代男性「健」**: ビジネスバッグを買い替え。耐久性、PC収納、自立するか、価格に対する満足度を比較したい。

### 代表ユーザーストーリー
- US1: 「ブランド名で検索して、人気商品をランキング順に見たい」
- US2: 「『A4が入る』『軽い』『マチが広い』で絞り込みたい」
- US3: 「実物の色感が知りたいので**写真付きレビュー**だけ見たい」
- US4: 「同じ身長・体型のユーザーのレビューを優先表示したい」
- US5: 「気になるバッグをクリップ保存して後で比較したい」
- US6: 「自分のバッグのレビューを書いて参考になったを集めたい」
- US7: 「カテゴリ別ランキング（トート / ショルダー / リュック / ビジネス）を見たい」
- US8: 「中古で買う前に真贋・状態の見分け方を知りたい」（Phase 2）

## 3. コアコンセプトと差別化ポイント

### コンセプト
> **「バッグの"使ってわかる"を、みんなで残す。」**

### 差別化
1. **バッグ特化の評価軸** — コスメと違う「収納力・重さ・素材・金具」など、バッグ固有の項目を最初から設計
2. **コーデ写真と一体化したレビュー** — 着用シーン・身長/体型タグでフィルタ可能（LIPS的UGC × バッグドメイン）
3. **「失敗ポイント」を明文化** — 「思ったより重い」「色が暗かった」など、購入後ギャップを定型項目で集計
4. **正規流通のみにリンク** — 購入導線は**ブランド公式 / 百貨店EC / 鑑定付きマーケット**に限定し、偽物リスクをゼロに。Amazon / 楽天の出品者商品は原則扱わない

### キャッチコピー案
- 案A: 「使った人だけが知ってる、バッグの本音。」
- 案B: 「カバン選び、もう失敗しない。」
- 案C: 「Bag Reviews by Real Users.」
- 案D: 「本物だけを、本音のレビューで。」（正規流通コンセプト寄り）

## 4. バッグ特有の評価軸

### 総合評価
- ★1〜5（必須）

### サブ評価（5段階、グラフで集計表示）
| 評価軸 | 説明 |
|---|---|
| 収納力 | 容量・仕切り・ポケット数の満足度 |
| 軽さ | 持った時の負担感 |
| 素材の質感 | 写真と実物のギャップを含む |
| 金具・縫製の丈夫さ | 経年使用での耐久性 |
| デザイン | 見た目の満足度 |
| コーデ合わせやすさ | 服装との相性 |
| 価格満足度 | 価格に対する価値 |

### 構造化タグ（複数選択）
- **入る物**: A4書類 / 13インチPC / 15インチPC / ペットボトル / 折り畳み傘 / 化粧ポーチ
- **シーン**: 通勤 / 通学 / お出かけ / 旅行 / フォーマル / アウトドア
- **特徴**: 自立する / 軽い / 防水 / 拡張可能 / 仕切り多い

### レビュアー属性（任意・絞り込み用）
- 身長レンジ（〜150 / 150-160 / 160-170 / 170+）
- 体型タグ（華奢 / 標準 / がっしり）
- 普段の荷物量（少なめ / 標準 / 多め）
- 年代（10代 / 20代 / ...）

### 自由記述
- 「良かったポイント」「気になったポイント」を分けて入力
- 写真アップロード（最大 5 枚）

### 購入情報（任意）
- 購入時期、購入店、購入価格

## 5. 情報設計（IA）とページ構成

### URL 構造
| URL | ページ | 主目的 |
|---|---|---|
| `/` | トップ | ランキング・新着レビュー・人気ブランド |
| `/brands` | ブランド一覧 | 五十音・人気順で探す |
| `/brands/[slug]` | ブランド詳細 | ブランドの紹介 + 商品一覧 |
| `/categories/[slug]` | カテゴリ一覧 | トート/ショルダー/リュック/ビジネス etc. |
| `/bags/[id]` | 商品詳細 | スペック・★集計・レビュー一覧・関連商品 |
| `/bags/[id]/reviews/new` | レビュー投稿 | フォーム |
| `/reviews/[id]` | レビュー単体 | 個別パーマリンク（SNSシェア用）|
| `/search?q=` | 検索結果 | 商品名・タグ横断検索 |
| `/rankings` | ランキング | カテゴリ別・期間別 |
| `/users/[id]` | プロフィール | 投稿レビュー・クリップ |
| `/login` `/signup` | 認証 | |
| `/clips` | クリップ一覧 | 自分の保存リスト |

### 主要導線
- トップ → ランキング → 商品詳細 → レビュー投稿
- ブランド検索 → ブランド詳細 → 商品詳細 → クリップ保存
- 商品詳細 → 類似商品 / 同ブランド他商品

## 6. 主要画面ワイヤー（テキストベース）

### 6.1 トップページ
```
┌─ Header: ロゴ / 検索バー / ログイン / クリップ
├─ Hero: 「バッグの本音、ここに。」+ 検索CTA
├─ 今週のランキング（カテゴリ別タブ：トート/ショルダー/リュック/ビジネス）
├─ 新着レビュー（写真付きカード横スクロール）
├─ 人気ブランド（ロゴ一覧）
├─ 編集部ピックアップ（特集記事）※Phase 2
└─ Footer: About / 規約 / プライバシー
```

### 6.2 商品詳細
```
┌─ Header
├─ パンくず: ブランド > カテゴリ > 商品名
├─ 左カラム: 商品画像ギャラリー（公式 + UGC写真）
├─ 右カラム:
│   ├─ ブランド名 / 商品名
│   ├─ 総合 ★4.3 (123 reviews)
│   ├─ サブ評価バーチャート（収納力 4.5 / 軽さ 3.2 ...）
│   ├─ スペック表（サイズ / 重量 / 素材 / 価格帯）
│   └─ [クリップ保存] [レビューを書く] CTA
├─ レビュー一覧
│   ├─ 絞り込み: 写真付きのみ / 身長 / 用途タグ
│   ├─ 並べ替え: 新着 / 参考になった順 / 評価高/低
│   └─ レビューカード（★ / サブ評価 / タグ / 本文 / 写真 / 投稿者属性 / 参考になった👍）
├─ 関連商品（同ブランド・同カテゴリ）
└─ Footer
```

### 6.3 レビュー投稿フォーム
```
ステップ1: 商品確認（写真・名前）
ステップ2: 総合 ★ + サブ評価 7 項目
ステップ3: タグ選択（入る物 / シーン / 特徴）
ステップ4: 良かった点 / 気になった点（自由記述）
ステップ5: 写真アップロード（任意・最大5枚）
ステップ6: 自分の属性（身長/体型/荷物量・任意）
[投稿する]
```

### 6.4 ブランド詳細
```
┌─ ブランドロゴ + 紹介文
├─ 商品グリッド（人気順 / 新着順）
├─ ブランド全体の傾向タグ（「軽い」「上品」「カジュアル」）
└─ そのブランドのトップレビュアー
```

## 8. 推奨技術スタック（提案）

| レイヤ | 推奨 | 理由 |
|---|---|---|
| フロントエンド | **Next.js (App Router) + TypeScript** | SSR/SSG で SEO に強い（口コミサイトはSEOが命）。コンポーネント開発しやすい |
| UI | **Tailwind CSS + shadcn/ui** | 高速プロトタイピング。デザイン統一しやすい |
| バックエンド | Next.js API Routes (MVPは同居) → 将来的に分離 | MVP は薄く |
| ORM | **Prisma** | スキーマ管理・マイグレーション・型安全 |
| DB | **SQLite (MVP) → PostgreSQL (本番)** | MVPはシンプルに、本番でフルテキスト検索や同時接続対応 |
| 認証 | **Auth.js (NextAuth)** | Google/Email 簡単 |
| ホスティング | **Vercel** | Next.js と相性最高、無料枠で始められる |
| 画像 | Phase 2 で **Cloudinary** | 自動リサイズ・最適化 |
| 検索 | MVP は ILIKE、Phase 2 で Meilisearch | |

## 9. デザイン方針

### トーン＆マナー
- **上品さとカジュアルさの中間**。@cosme のような明るさよりも、もう少し落ち着いたエディトリアル感を意識。
- 高級ブランドも扱うので、ブランド表記やフォントは抑制的に。

### カラーパレット案
- ベース: アイボリー / オフホワイト (#F8F6F2)
- アクセント: 深みのあるブラウン or バーガンディ (#7A4D3C / #6E2C3F)
- テキスト: チャコール (#222)
- 評価★: ゴールド (#D4A24E)

### タイポグラフィ
- 日本語: Noto Sans JP（読みやすさ優先）
- 欧文・ブランド名: Playfair Display や Cormorant Garamond でエディトリアル感

### ビジュアル参考
- @cosme（情報設計の参考）
- LIPS（UGC 写真の見せ方）
- Vestiaire Collective（高級感のある写真表示）
- Pinterest（カードレイアウトのインスピレーション）

## 10. ビジネスモデル

### 方針
**Phase 1 は「正規流通のみ」に絞ったアフィリエイトで立ち上げる**。
偽物問題を避けたいユーザーに「ここなら安心して買える」と感じてもらうことが、単なるレビュー集約サイトとの明確な差別化になる。

### 収益構造の段階

| Phase | 主な収益源 | 開始条件の目安 | メモ |
|---|---|---|---|
| **Phase 1** | **正規EC アフィリエイト** | ローンチ〜月間UU 1万 | ブランド公式 / 百貨店EC / 鑑定付きマーケット限定 |
| **Phase 2** | タイアップ記事 / 純広告 | 月間UU 5〜10万 | ブランドから新商品PR案件 |
| **Phase 3** | B2B データ販売（インサイト提供） | 月間UU 30万〜 | 構造化レビューを活かす、@cosme for BUSINESS 型 |
| **Phase 4** | 自社EC / セレクト販売 | 後続検討 | 評価データでキュレーション |

### Phase 1 アフィリエイト対象（例）
- **ブランド公式サイト**: COACH公式、Kate Spade公式、土屋鞄、吉田カバン/PORTER 等
- **百貨店 EC**: 三越伊勢丹オンライン、大丸松坂屋オンライン、高島屋オンライン
- **鑑定付きマーケット**: BUYMA（正規取扱店舗）、Vestiaire Collective（鑑定済）
- **除外方針**: Amazon / 楽天の非公式出品、メルカリ等の C2C（真贋保証が弱い）

※ 具体的に提携可能なアフィリエイトプログラム（A8.net / バリューコマース / Rakuten Advertising / 各ブランド個別プログラム）は実装前に別途リサーチ。

### 設計へのインパクト
- **商品テーブルに「購入リンク」サブテーブル**（複数 EC に 1 商品が紐づく）
- **各リンクに「正規度ラベル」**（official / department-store / authenticated-marketplace）
- **管理画面でアフィリエイト URL 管理 & クリック計測**
- **レビューデータの構造化は Phase 3 を見据えて最初から丁寧に**（サブ評価/タグを後から変えづらい）
